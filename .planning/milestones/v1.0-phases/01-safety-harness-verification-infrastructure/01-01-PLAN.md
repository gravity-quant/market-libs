<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| credential value → stdout/log/report | A token or password loaded from env may be passed into a print/log; this is where leakage occurs (HARN-03) |
| live test → CI runner | A `@pytest.mark.live` test must never execute in CI by default (HARN-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `redact()` / driver print sites | mitigate | `redact(value, keep=4)` returns only a 4-char prefix + ellipsis; full value never reachable from the return path (HARN-03/D-13) |
| T-01-02 | Information Disclosure | `safe_print()` second layer | mitigate | safe_print masks any known credential (>= 4 chars) found anywhere in the output string — a leak via an accidental raw-dict print is masked structurally, not by discipline (D-13) |
| T-01-03 | Reliability / output corruption | `safe_print()` with empty/short secret | mitigate | `len(secret) >= 4` guard prevents `str.replace("", marker)` from wedging the marker between every character (VERIFIED concourse #4656) |
| T-01-04 | Tampering (test scope) | `live` marker default | mitigate | deselect-by-default in `pytest_collection_modifyitems`; CI runs `uv run pytest` (no `--live`) → live tests never fire; `--strict-markers` guarantees the marker is registered, not silently typo-skipped |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (stdlib + already-present `pytest` only; RESEARCH Package Legitimacy Audit = none) |
</threat_model>

## Corrections Made

Both open items were presented to the operator as choices; both took the recommended option.

### Version Number & Non-Breaking Classification — `CalendarDay`

- **Question:** `CalendarDay` lost `date`/`marketId`/`isBusinessDay` (`831f44f`) and is exported
  since v0.2.0. D-13 pre-authorized it as non-breaking but that claim was never independently
  audited. How to ship?
- **Operator choice:** **`0.4.0` + changelog callout** — honor the locked D-13 rationale, ship
  as minor, but the `v0.4.0` changelog must explicitly name the field replacement so it is
  discoverable rather than silent.
- **Alternatives rejected:** compat shim with deprecated aliases (the `Symbol.marketId`
  pattern); escalating to `1.0.0` (contradicts locked D-13/D-22 and burns the major that
  `models.py`'s `Symbol` docstring reserves for removing the `marketId` alias).
- **Recorded as:** D-03.

### CI Green Gate — mypy / import-linter enrolment

- **Question:** the package is still absent from the root mypy `files` list and import-linter
  `root_packages`, a follow-up carried since Phase 24. Enrol now or keep deferred?
- **Operator choice:** **Keep deferred, file to v1.6** — the release PR stays strictly
  release-scoped, and the item gets an explicit v1.6 backlog entry so it stops silently rolling
  forward release to release.
- **Alternatives rejected:** enrolling in this PR (would expand the release diff); leaving it
  with no backlog entry (status quo, keeps carrying implicitly).
- **Recorded as:** D-16.

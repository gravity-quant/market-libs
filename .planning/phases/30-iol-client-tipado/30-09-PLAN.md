  id: "AD-30-09-01"
  question: >
    Apply the redaction as one shared helper inside main_iol.py called from all 31 sites, or add a
    sink-side guard inside verification/findings.py that rejects unredacted exception-shaped values
    for every driver at once?
  chosen: "one shared helper inside main_iol.py (emitter-side), extending AD-30-08-01"
  reversibility: "two-way"
  rationale: >
    This re-ratifies AD-30-08-01 at larger scale rather than reopening it. A sink-side guard in
    findings.py would have to decide, from a finished string, which substrings are wire values —
    the type information that makes the decision trivial is gone by the time append_finding is
    reached. Worse, the guard would be a shared harness module governing six drivers, so a
    false positive would block an unrelated driver's finding and a false negative would give every
    driver a guarantee none of them can inspect. The emitter still holds the exception object and
    can name the two safe facts (class, status code) plus, for IOLDecodeError, four attributes the
    package's own docstring certifies as type-only. Choosing a helper over 31 inline copies is the
    substantive change from 30-08: with one call site an inline expression is defensible, with 31

    function plus a mechanical substitution inside one non-published driver script, guarded by a
    new test file; no package source, no committed baseline, no public API, no shared harness
    module, no dependency.

<objective>
Close the BLOCKER that 30-VERIFICATION.md's third cycle re-derived independently and 30-REVIEW.md
filed as CR-01: the reasoning 30-08 wrote down is correct and general, but it was applied at one of
the 31 places in `main_iol.py` where an exception is stringified into a report.

`_core.raise_for_response` puts the entire upstream response body into the exception's own message,
for the benefit of the consumer who must debug it. `append_finding` writes its arguments verbatim
into `.planning/verification/iol-client-findings.md`, which `git ls-files` confirms is tracked. On
an authenticated run against a real brokerage API an error body plausibly carries account and
instrument identifiers, and once committed the exposure is permanent and distributed on push.
`probe_refresh_token` (line 1587) fires after a deliberately forced token expiry on a live
authenticated call; `probe_auth_401` (line 1742) fires immediately after a login attempt made with a
deliberately invalid password. Neither is a hypothetical branch — both are the ordinary failure path
of a live verification run against a third party whose availability the project charter calls
unreliable.

Purpose: make the rule the driver already states about itself true everywhere it applies. Three
statements this project has already ratified are false about these 31 code paths today —
`_capture_raw_wire`'s own docstring (`main_iol.py:264-272`), `exceptions.py`'s T-29-36 invariant
("tipos y rutas, jamás un valor del wire"), and CLAUDE.md's constraint against exposing sensitive
data in logs, reports or tests. The committed findings artifact happens to be clean today; the code
paths are live.

The substantive design change from 30-08 (AD-30-09-01): the redaction becomes one named function
rather than an inline expression. At one call site an inline expression is defensible; at 31 it
becomes 31 independent decisions that will drift, which is precisely how this gap came to exist.

Secondary, closed here rather than deferred: blanket-applying 30-08's shape would render an
`IOLDecodeError` as a class name and a null status code, discarding the four attributes
`exceptions.py:40-46` certifies as type-only and therefore already reportable in full (WR-03). A
helper that over-redacts at 31 sites is materially worse than one that over-redacts at 1, so the
special case is part of the helper's contract, not a follow-up.

Output: `main_iol.py` with a single sanctioned exception renderer and all 31 sites routed through
it, plus a new offline test file that pins the helper's contract, proves end-to-end that no probe
finding carries a planted wire marker, and locks the pattern out of the file's future by AST.
</objective>

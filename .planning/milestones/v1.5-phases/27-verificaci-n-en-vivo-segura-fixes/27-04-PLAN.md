<objective>
Add the symbols half of the destructive live cycle to `main_market_data.py`: the shared,
gate-safe mutation plumbing plus the create -> verify -> revert probes on both surfaces, with
the idempotency experiment folded into the same sequence.

This is the repo's first destructive live verification, so the plumbing is designed here rather
than copied (D-25). Two traps are load-bearing. First, the driver's existing raw dispatch helper
calls `client._request(spec)` directly and `_request` does **not** invoke
`_ensure_mutation_allowed()` — routing a mutation spec through it would fire a real write with
the gate possibly closed, against whatever host (Pitfall 4). Second, `DELETE /symbols` does not
exist anywhere in the live spec, so the only possible revert is `PATCH active=false`, and every
run leaves one permanently inactive row per identifier — the dedicated prefix is what turns a
permanent residue into an auditable one (D-05).

Purpose: ROADMAP criteria 1, 2 and 3 for the symbols surface — exercised behind the gate, with
dedicated identifiers and a completed cleanup cycle, and with assumed idempotency (DM-03)
revalidated against measured live behaviour rather than spec prose.
Output: gate-checked dispatch helpers, a cleanup-finding helper, stable test identifiers, eight
symbols probes, and two AST guards that make the two traps above impossible to reintroduce.

**Nothing in this plan runs against develop.** All of it is verified offline with the gate
closed; the armed run is plan 27-06.
</objective>

<objective>
Publish the per-package divergence floor that becomes the declared budget for
the live-verification phase.

The roadmap identifies the wrong corpus for this run: the directory it names
holds public-surface text files with no payloads in them. The real corpus is the
43 type-only schema JSON files captured per package. That corpus supports a
keyset-and-type floor and nothing more, which is exactly what a floor should be.

Purpose: the milestone's largest standing risk is that years of silent tolerance
have hidden an unknown volume of divergences, and the first strict run uncovers
all of them at once and overruns the milestone. This measurement is the agreed
mitigation, and it must run before the later phases are committed to.
Output: `29-SIZING.md` with a per-package lower bound, the full mapping table,
the method, the blind spot, the freshness statement, and an operator signature.

Decisions implemented: D-06 (the count is produced by the shipped walker with the
schema-reducer vocabulary, so the floor is directly contrastable with the live
census the next phase runs), D-08 (the corpus is rebased onto the type-only
schema directory, the floor is a keyset-and-type lower bound expressed as
greater-than-or-equal, and both the blind spot and the capture freshness are
stated in writing).
</objective>

  <action>
Write a throwaway script into the session scratch directory. It is not committed
and it is not shipped; the deliverable is the report.

Method, in order:

1. Build a mapping table covering all 43 corpus files. For each file, resolve the
   owning package, the response parser that handles that endpoint, and the model
   class the parser produces. Derive the mapping from the drivers that wrote the
   files: several file names are probe names rather than API function names, so
   automatic resolution from the recorded function name succeeds for well under
   half the corpus. Where no model exists — a package with no models module, or
   an endpoint that still returns an untyped mapping, or an endpoint returning a
   bare scalar — mark the row not applicable with the specific reason. Every one
   of the 43 files gets a row. A file with no row is an undercount and fails this
   task.
2. Synthesize a witness payload from each file's type-only schema by inverting
   the reduction: a mapping becomes a mapping of the same keys with synthesized
   values, a one-element sequence becomes a one-element sequence of a synthesized
   element, an empty sequence stays empty, and a scalar type name becomes that
   type's zero value with the null type name becoming the null value.
3. Wrap each witness in a synthesized successful HTTP response object and call
   the owning package's own parser with it. Do not map a schema file straight to
   a model class: the corpus stores the raw wire payload while the models
   describe the unwrapped item, and walking the raw wrapper against the model
   produces a flood of artificial missing and extra reports. Re-deriving the
   unwrap key is also how a previously shipped bug in this repo happened. Going
   through the parser also makes the number directly comparable with the live
   census the next phase runs.
4. Decode in observable mode with a counting handler attached to the package
   logger, and count unique divergence records — the walker already collapses
   repeats within a decode scope, so the count is per unique triple.
5. Aggregate per package and per file, split by divergence kind.

Then write `.planning/phases/29-decoder-observable/29-SIZING.md`:

- **Method** — the five steps above, stated so the run is reproducible, plus the
  note that the corpus identified in the roadmap for this criterion holds
  public-surface text files with no payloads and the real corpus is the schema
  directory.
- **Mapping table** — all 43 rows: file, package, parser, model, or the
  not-applicable reason.
- **Floor table** — per package, expressed as a lower bound with the
  greater-than-or-equal form, never a bare number. The two packages with no
  models module are reported as not applicable with a written reason, never as
  zero; a zero would read as clean, and a false clean is the failure mode this
  whole milestone exists to remove.
- **Breakdown by kind** — how much of each package's floor is a missing field, a
  wrong type, an extra wire key or a non-dict payload. Call out the dominant
  class explicitly: the expected dominant finding is a declared non-nullable
  scalar arriving as null, which today is silently substituted with a typed zero,
  and that is precisely the substitution this phase makes observable.
- **Structural findings** — any row where the model and the wire disagree
  structurally rather than incidentally. Flag each as a candidate finding for the
  live-verification phase with the package and field named.
- **Blind spot** — in writing: a type-only corpus cannot see value-level
  divergences such as non-finite numbers or enumeration values outside a declared
  set. Those are exactly the class the response-Literal policy defers to the live
  census, so the floor understates the live number by an unknown margin in that
  direction.
- **Freshness** — the oldest and newest capture dates per package, read from each
  file's recorded capture timestamp, with a sentence stating that staleness
  weakens the floor's currency but not its validity as a lower bound.
- **Consequence** — one paragraph stating that this number is the declared budget
  for the live-verification phase, and that exceeding it there requires an
  explicit re-scope with deferred findings routed to a named destination phase
  rather than being silenced.
- An unsigned signature line.

Do not commit the script. Do not modify any package source.

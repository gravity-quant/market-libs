<objective>
Settle the single **one-way** decision in Phase 32 before any code depends on it.

The sync/async parity test that Plan 32-04 builds will find a real divergence on its first run:
`market_data_client.aio.configure` (`aio.py:776-788`) does not accept `http_client`, while
`market_data_client.client.configure` (`client.py:762-775`) does — and the async docstring at
`aio.py:797-798` claims the semantics "ESPEJA exactamente" the sync surface. This is drift
documented as non-existent, and market-data is the only one of the six packages with the
asymmetry.

Closing it means adding a parameter to the **public API of an already-published package**
(`market-data-client` v0.4.0) that Phase 34 will re-publish. Adding a public keyword-only
parameter is additive and not source-breaking, but it is not undoable: once shipped, removing it
later is a breaking change. That makes this a one-way door, and one-way doors get a decision
gate before the task that walks through them.

Purpose: make the irreversible choice explicitly, with the tradeoffs written down.
Output: a recorded disposition that Plan 32-04 reads before touching `aio.py`.
</objective>

  <decision>
    How should Phase 32 dispose of the D-09 finding — `market_data_client.aio.configure` missing
    the `http_client` parameter that its own docstring claims it mirrors?
  </decision>
  <context>
    The parity test in Plan 32-04 compares `typing.get_type_hints()` between `client.py` and
    `aio.py` for every shared public module-level name, after applying a small sanctioned
    normalization table (`httpx.Client` ↔ `httpx.AsyncClient`, `Client` ↔ `AsyncClient`,
    `aclose` async-only). Research measured that this comparison finds exactly six divergences
    across the six packages: five are the legitimate `httpx.Client` vs `httpx.AsyncClient` shift
    on `configure(http_client=)`, which the normalization rule dissolves, and the sixth is
    market-data's — where the parameter is not type-shifted but **absent entirely**.

    So on the first run of the parity suite, market-data is the one package that stays red. It
    cannot be left red without an explanation, and CONTEXT.md D-09 says as much.

    Why this is a one-way door: `market-data-client` is published at v0.4.0 and Phase 34
    re-publishes the packages whose surface changed. A keyword-only parameter added now is
    additive (not source-breaking, no semver-major implication) but permanent — withdrawing it
    later would be the breaking change. The allowlist route, by contrast, is a test-only artefact
    that can be deleted at any time with no consumer impact.

    Cost and risk of option A are both small and precedented: `AsyncClient.__init__`,
    `_ClientState.http_client` and `aio.aclose()` already support everything needed, so the change
    is confined to `configure`'s signature, one carry-forward block in its body, an
    `import warnings` at module scope (market-data's `aio.py` does not currently import it), and
    the docstring line that currently over-claims.

    The known objection to option A — that a plain `def configure` cannot `await` the old
    client's `aclose()` before swapping it — is exactly the objection matriz and iol already
    answered by emitting a `ResourceWarning` and swapping anyway. That is why research rates
    option A HIGH confidence rather than a judgement call.

    Note the scope boundary either way: `verification/test_async_configure_resource_warning.py`
    carries a three-package roster (ambito, iol, higyrus) that excludes market-data. Enrolling
    market-data there is one of the ~6 out-of-scope rosters D-12 defers; it is **not** part of
    this decision and must not be folded in.
  </context>
  <options>
    <option id="option-a">
      <name>Close the drift — add `http_client: httpx.AsyncClient | None = None` to `market_data_client.aio.configure`</name>
      <pros>
Makes the docstring's existing parity claim true instead of aspirational. Removes the exact class of silent divergence this milestone exists to eliminate — leaving it is choosing to keep one. Purely additive keyword-only parameter, so not source-breaking; a minor-worthy changelog note for Phase 34, nothing more. Fully precedented: four of the five other packages already thread `http_client` into their async `configure`, two of them via the `ResourceWarning` shape that market-data would copy. Zero type changes needed anywhere else — `AsyncClient.__init__`, `_ClientState.http_client` and `aio.aclose()` already support it. Satisfies CLAUDE.md's dual sync/async mirroring constraint, which arguably makes it obligatory rather than optional. Lets the parity test compare full `get_type_hints()`, which is what criterion 3 literally asks for.
      </pros>
      <cons>
Changes the public surface of a package that is already published and is a Phase 34 re-publish candidate — irreversible in the sense that the parameter cannot later be withdrawn without a breaking change. Adds a new `ResourceWarning` emission path that consumers running under `-W error` could trip. Marginally widens what Phase 34's changelog must cover.
      </cons>
    </option>
    <option id="option-b">
      <name>Leave the surface alone — allowlist `configure` from the full-hint comparison and compare only parameter-name sets</name>
      <pros>
Zero change to a published public API; fully reversible, since the allowlist is a test-only artefact. Still catches the missing `http_client` (the name is absent from the async side, so a name-set comparison flags it) without requiring identical type hints. Keeps Phase 34's changelog for market-data narrower.
      </pros>
      <cons>
Weaker than criterion 3's literal wording, which says the test "compara `get_type_hints()`". Leaves the `aio.py:797-798` docstring making a false parity claim, so the repo keeps documenting a divergence as non-existent. Creates the phase's first normalization exception that exists to accommodate a defect rather than a legitimate difference — precisely the pattern `check_decode_intactness.py`'s rule-table framing warns against ("never weaken the check into a vacuous one"). Defers the fix to a phase with less context than this one has.
      </cons>
    </option>
  </options>

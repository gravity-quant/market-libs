<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller kwargs → query params | client-owned typed kwargs funneled through drop_none, encoded by httpx |
| server response → parser | untrusted JSON body deserialized after body-consume + status check |

## STRIDE Threat Register (ASVS L1, block-on-high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02-01 | Tampering | query-param injection via filter kwargs | mitigate | Params are typed kwargs; httpx encodes them (no string concatenation into the URL). drop_none only strips None. Severity: low. |
| T-21-02-02 | Denial of Service | retry amplification via idempotent=True | mitigate | idempotent-gated retries are bounded by the transport's max_attempts (per-call cap wired in Plans 03/04); GET/read-shaped POST only. Severity: low. |
| T-21-02-03 | Information Disclosure | parser surfacing response text into an exception message | accept | raise_for_response includes resp.text on error, but market-data responses carry no credentials; RedactingFilter covers log sites. Severity: low. |
| T-21-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this plan (zero new deps). No checkpoint required. |
</threat_model>

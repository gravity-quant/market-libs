<objective>
Run the destructive cycle against develop, once, under explicit operator authorization, and
capture the evidence that only the live server can produce.

Three questions cannot be answered offline and gate every fix in plan 27-07. Where does the
integer symbol row id live — the spec says `GET /symbols` returns it but declares the item
schema as an untyped object (D-10). What do the eight mutation responses actually contain — the
OpenAPI declares every one of them as a bare `object` with no schema, which is why
`parse_symbols_response` producing one all-default `Symbol` per JSON key has never been visible
(D-11). And does each endpoint really dedupe — the spec claims `POST /symbols` and
`POST /calendar/holidays` are idempotent, but D-19 forbids inferring idempotency from prose and
D-20 makes measured reality authoritative.

Purpose: this is the phase's live evidence, and ROADMAP criteria 1, 2 and 3 are only satisfied
by a real armed run.
Output: a captured armed-run transcript, new findings above F-36, new mutation-body baselines,
a proven-zero residue, and a consolidated evidence record that plan 27-07 consumes.

**A SKIPPED run is a legitimate outcome, not a failure.** If credentials are absent, if develop
is unreachable, or if the operator declines authorization, the driver exits SKIPPED per D-03/D-04
and this plan records "apparatus verified, live evidence not obtained" — exactly the disposition
Phase 23 used. In that case plan 27-07 executes only the fixes whose evidence is already
available offline, and the remainder carries forward explicitly rather than being silently
dropped.
</objective>

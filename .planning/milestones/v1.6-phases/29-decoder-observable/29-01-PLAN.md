Write two artifacts.

**A. `29-AGGREGATION-CONTRACT.md`** — the anti-log-spam and record-shape
contract. It must state, as numbered locks:

1. Record schema — exactly six `extra` keys, all `str` values, all top level,
   no nested containers: `package`, `divergence`, `field_path`,
   `declared_type`, `observed_type`, `model`. The log message is the constant
   string `decode divergence`. `model` carries the bare class name, never a
   dotted path. `declared_type` and `observed_type` use the `schema_of`
   vocabulary, i.e. the value of `type(x).__name__`; for a divergence of kind
   `extra` there is no declared type and the value is the single character `-`.
   Justify the key set against the reserved `LogRecord` attribute names: the
   natural names for "which module" and "which model" collide with reserved
   attributes and make `Logger.makeRecord` raise, which would turn observable
   mode fatal. State the reserved names the schema deliberately avoids.
2. Divergence kinds — exactly four: `missing`, `type`, `extra`, `non_dict`.
   Define each in one sentence.
3. Level map — `missing`, `type`, `non_dict` emit at WARNING; `extra` emits at
   INFO. Reason: extra wire keys are the normal result of vendor API growth and
   must not drown the real signal.
4. **Open decision 1, RESOLVED:** strict mode raises on `missing`, `type` and
   `non_dict`, and **never** on `extra`. Record the reasoning: reading criterion
   2 literally would make Phase 33's strict driver run fail on every legitimate
   new vendor field, which is a divergence storm by construction and would force
   Phase 33 to absorb every upstream field addition as a blocking finding.
5. **Open decision 2, RESOLVED:** the dedupe key is the triple
   `(model, field_path, kind)`. It deliberately excludes the list index — a
   `list[X]` element contributes the path segment `[]` with no index, so N rows
   diverging identically collapse to one record. Distinct kinds at the same path
   stay distinct records.
6. Scope — a *decode scope*. `_request` binds a fresh decode scope at its top
   (same `.set()`-without-reset discipline as the mode) so every model decoded
   from one HTTP response, including every element of a top-level `list[Model]`
   parse, shares one scope. When no scope is bound — a direct `Model.from_api()`
   call with no preceding request — the outermost `walk_model` creates a
   per-call scope. Explicitly reject a process-lifetime scope: it would make the
   second identical response decode silently clean.
7. Emission timing and ordering — emit eagerly at the first occurrence of a key
   within the scope and suppress every later occurrence of the same key. State
   why no `occurrences` counter is carried: a count requires a flush phase, two
   emission modes, and loses records if the process dies mid-decode, while the
   phase criterion asks for exactly one record per divergent field. Aggregate
   counting is Phase 33's job via the findings pipeline. Document the emission
   order as deterministic: within one `walk_model`, extra keys first in sorted
   key order, then declared fields in `dataclasses.fields()` declaration order,
   recursing depth-first — stable across runs for the same payload.
8. Non-dict is terminal for reporting — when a payload is not a dict, emit
   exactly one `non_dict` record for that model and suppress the per-field
   `missing` records it would otherwise imply. Without this, a legitimate 204 or
   a null body would emit one record per declared field. An empty dict `{}` is a
   dict and does report per-field `missing`.
9. Emitter safety — the emit call is wrapped so that a failure inside logging or
   inside a consumer's handler can never propagate into the decode return path.
   Observable mode raising from its own emitter is the inversion of the whole
   policy change.
10. Findings compatibility (D-06) — the six keys must be consumable by
    `verification/findings.py::append_finding` in Phase 33 without translation;
    name the `SHAPE` finding class as the target and map each record key to its
    finding field.
11. Redaction posture (D-05) — the record contract is the primary control and
    the `RedactingFilter` fix is defense in depth. State plainly that no filter
    change makes a wire value safe to log, because the redaction passes are
    marker-anchored regexes and a bare credential matches none of them.
12. Filter recursion bound — the filter fix traverses nested containers, so it
    carries an explicit depth bound of 4 and skips containers with more than 64
    entries, so a hostile payload cannot turn a log filter into a CPU sink.

**B. `29-DLOCK-RESPONSE-LITERAL.md`** — the D-09 sign-off. State: response
fields are never closed as `Literal` in this milestone; they decode as `str` and
an out-of-set value is reported as a divergence and returned unchanged. The
walker gets an explicit branch for `Literal` hints that (a) never enforces
membership and (b) does validate the underlying runtime type of the literal's
members, so a wire `int` where a str-valued `Literal` is declared still reports
a `type` divergence — silence on out-of-set values, loudness on wrong runtime
type. List the nine matriz `types.py` aliases the policy reaches retroactively.
Record the evidence that the change is behaviorally free for matriz: `_convert`
today ends in a bare pass-through return, so these fields are already unvalidated
and the change is reporting-only. State the consequence for Phase 33: closing
any of these with a live census is deferred, and doing it early would be a
silent behavior break on published surface. End with an operator signature line
(`Signed:` / `Date:`) left blank for the checkpoint.

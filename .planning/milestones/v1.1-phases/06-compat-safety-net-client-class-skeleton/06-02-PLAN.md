<objective>
Ship the Pitfall #1 mitigation: a guard test per package that proves a sentinel token monkeypatched onto the legacy module-level state actually reaches the wire-level `Authorization` / `X-Auth-Token` header (or `base_url` for the no-auth ambito case) of an outgoing httpx request. This safety net runs green NOW against the current code, and re-runs green AFTER each per-package refactor (Plans 03-06) lands — proving that the conftest migration plus PEP 562 shim plus instance-state semantics preserve test reach.

Purpose: STATE.md Blockers explicitly require this guard test to "EXIST and PASS BEFORE the first Client class refactor lands per-package". The 277 mocked test baseline does not catch a `monkeypatch.setattr(... raising=False)` landing on a dead address — only this guard does (RESEARCH.md Pitfall #1).

**Per-package placement (resolves checker B1/B2/B3):** RESEARCH.md Architectural Responsibility Map and VALIDATION.md Wave 0 Gaps both place the guard tests inside each package's own `tests/` directory. Putting all 4 guards in a single shared `verification/test_fixture_reaches_production.py` would force Plans 03/04/05/06 to mutate the same file concurrently in Wave 1 — a write conflict. With per-package files, each Wave 1 plan owns exactly one guard file. `depends_on` for Plans 03/04/05/06 collapses to `[06-01, 06-02]` — no inter-Plan-1 ordering needed because no shared file. Each per-package plan then migrates its OWN guard file from the legacy `monkeypatch.setattr` pattern to `pkg.configure(token=...)` atomically as part of the per-package commit.

Output: 4 new test files, one per package:

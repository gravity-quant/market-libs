  <behavior>
    Sujeto: `main_market_data._write_schema_snapshot(*, endpoint, client_function, raw, base_url, surface) -> None`,
    con un baseline committeado que YA difiere del payload que se le pasa.

    - Caso a (COLAPSO): dos llamadas con el mismo `client_function` y el mismo `raw`
      (superficies `"sync"` y `"async"`, que es la duplicación real medida: 22 bloques → 11)
      → **1** bloque `### F-` nuevo en el findings file.
    - Caso b (NO-COLAPSO, falsificación): dos llamadas con el mismo `client_function` y `raw`
      **distintos** (schema distinto ⇒ digest distinto) → **2** bloques `### F-` nuevos.
    - Caso c (FID NO QUEMADO): partiendo de `_fid_counter == 0`, dos llamadas del caso a dejan
      `_fid_counter == 1`, no 2.
    - Invariante transversal: después de correr el archivo completo,
      `git status --porcelain .planning/verification/` sigue vacío.
  </behavior>
  <implementation>
    Estado module-level en el driver, junto a `_fid_counter`: un `set` de tuplas `(str, str)` y un
    helper de digest determinístico. La guarda se consulta ANTES de `_next_fid()`; el no-op es un
    `return` desnudo porque el helper de market-data devuelve `None`.
  </implementation>
</feature>

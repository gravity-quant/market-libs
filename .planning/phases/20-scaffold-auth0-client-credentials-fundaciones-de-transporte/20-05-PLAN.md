<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| async client → Auth0 token URL | Absolute host; grant serialized by the per-loop token lock |
| async client → API | Bearer injected only when `spec.authenticated`; health anonymous |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-02 | Information Disclosure | token to health/wrong host | mitigate | `_send_auth_request` targets absolute `auth0_token_url`; `_request` gates Bearer on `spec.authenticated` |
| T-20-03 | Spoofing | stale token reuse | mitigate | `_aensure_token` double-checks `token_is_fresh` inside the token lock (60s buffer) |
| T-20-08 | Denial of Service | 401 re-auth loop / thundering-herd re-auth | mitigate | exactly-one re-auth then re-raise; double-checked lock serializes concurrent re-auth (D-12, not matriz TokenStore) |
| T-20-09 | Tampering | lock bound to wrong event loop | mitigate | locks created lazily per-loop on first async use (Pitfall 2), never in `__init__` |
</threat_model>

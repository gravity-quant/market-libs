<objective>
Fix `parse_latest_response` in `_core.py` so `get_latest_batch` (sync `Client.get_latest_batch` + async mirror) returns correctly-populated `MarketDataSnapshot`s instead of N empty ones.

Root cause (WR-01, deferred Phase 25 code review, now confirmed live): the batch `POST /marketdata/latest` returns an envelope object `{"requested","count","not_found","server_time","items":[...]}`, but `parse_latest_response` iterates `for item in raw` assuming a bare list. Iterating a dict yields its 5 string KEYS, each collapsing via `MarketDataSnapshot.from_api(<str>)` to defaults → N empty snapshots.

The sibling `parse_market_data_response` (same file, lines 588-616) already fixed this exact pattern (LIVE-MD-01). This plan reuses that unwrap pattern verbatim. `_core.py` is shared by `client.py` + `aio.py`, so ONE change covers sync + async.

Purpose: Restore batch-latest correctness — the last unfixed instance of the envelope-unwrap bug.
Output: Fixed parser + regression tests locking in both the envelope (batch POST) and bare-list (single GET) shapes.
</objective>

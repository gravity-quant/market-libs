<objective>
Close the post-closure half of CR-01: a captured JSON `null` body must be treated as a
payload that arrived, not as a capture that failed.

`_capture_raw_wire` stores `raw_by_endpoint[func_name] = resp.json()` on any 200 response.
When the endpoint answers `200` with a literal `null` body, that stores the Python value
`None` — which is precisely the value all three downstream consumers use as their
"capture failed" sentinel. The producer's own docstring states the opposite intent
verbatim: an endpoint whose capture raised is left **absent** from the dict, absent rather
than null, so that downstream nobody can confuse "not captured" with "captured as null".
The producer honors that contract. The consumers discard it by testing value identity
instead of dict membership.

Measured against the committed code, a fully null-bodied capture of all four endpoints
produces zero findings and two PASS results, and probe 12's PASS detail names three
endpoints as checked when none of them were inspected. This is the same failure class
30-06 was written to eliminate — a probe attesting to a comparison it never performed —
recurring in the one input class 30-06's nine-case regression lock does not exercise.

Purpose: restore the guarantee that a drift probe's PASS means something. The fix is four
predicates; the durable part is the regression case that pins the input class which
defeated the previous lock.

Output: `main_iol.py` with membership-gated probes, and `verification/test_main_iol_raw_wire_drift.py`
extended with null-body cases for both probes.
</objective>

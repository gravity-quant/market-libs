<objective>
Deliver the two hard safety gates as one vertical slice: `require_env` (HARN-01/D-15) which
emits the verbatim `SKIPPED <pkg>: missing X, Y` line and lets the caller exit cleanly, and
`mutating_allowed` (HARN-02/D-16) which makes Matriz order mutations unreachable unless both
`VERIFY_MUTATING=1` AND the live-resolved base URL contains `remarkets` — otherwise printing
`SKIPPED (mutating, guard off)`. Each is proven by a unit test, including the adversarial
"prod URL with the flag on" bypass attempt.

Purpose: These are the belt-and-suspenders controls that prevent (a) a partial live run
against a misconfigured target and (b) an accidental destructive order. Both must exist and
be proven before any later phase touches a live API. The exact SKIPPED strings are fixed by
the roadmap success criteria and must be verbatim.

Output: `verification/env_gate.py`, `verification/mutation_gate.py`, and their two harness
test files under `packages/ambito-financiero-client/tests/`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env (.env / shell) → driver run | Missing or partial credentials must produce a clean SKIP, never a partial live run against a misconfigured target (HARN-01) |
| driver → live mutating endpoint | An order-placement call must be unreachable unless explicitly opted in AND pointed at the sandbox (HARN-02) |
| configure(base_url=...) override → mutation guard | A runtime base-URL override to prod must not slip past the guard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering / Elevation | `mutating_allowed()` | mitigate | Double gate: `VERIFY_MUTATING == "1"` AND `"remarkets" in _base_url`; default returns False + prints `SKIPPED (mutating, guard off)` (HARN-02/D-16) |
| T-01-06 | Tampering (prod misconfig) | base-URL source in guard | mitigate | Guard reads the LIVE resolved `matriz_client.client._base_url` at call time (not a constant) so a `configure(base_url=prod)` override is caught (Pitfall 5); unit-proven by the adversarial prod-URL test |
| T-01-07 | Reliability / fail-safe | `require_env()` exit behavior | mitigate | require_env returns a bool and never raises/exits; missing creds → verbatim `SKIPPED <pkg>: missing X, Y` so the aggregate runner continues rather than running partially (HARN-01/D-15, Pitfall 6) |
| T-01-08 | Information Disclosure | reading `_base_url` private state | accept | Guard reads module state for the decision only and never echoes it (A2); no credential is read or printed here |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No package installs (stdlib + already-present `matriz_client` import only; RESEARCH Package Legitimacy Audit = none) |

<objective>
Add the calendar half of the destructive cycle plus the terminal safety probes: preview-only
config verification, the holidays create -> verify -> revert cycle, the residue sweep, the
self-inflicted health-feed recheck, and the snapshot policy that keeps mutation payloads from
polluting the divergence count.

Two decisions shape this plan and are not open. First, calendar config is **preview-only**
(D-06, operator ruling): `delete_calendar_config` resets to the server's defaults rather than
restoring a prior value, so a DELETE cannot serve as cleanup for a PUT, and any real PUT would
leave develop's shared configuration clobbered. `POST /calendar/config/preview` is documented
as writing nothing, so it is the one config write-path that is safe live. Second, holidays are
fully reversible — `DELETE /calendar/holidays/{day}` exists and the live spec states deleting
there is safe because nothing references those rows — making this the phase's only complete
create -> verify -> revert (D-07).

Purpose: ROADMAP criterion 2 ("real market config is never touched without `confirm`") and the
remainder of criterion 3. It also closes the loop opened by plan 27-02: `GET /calendar` is the
only read that can confirm a holiday landed, which is why the envelope unwrap had to ship first.
Output: preview probes, the holidays cycle on both surfaces, a terminal residue sweep, a
health-feed recheck that classifies our own contamination correctly, and an AST guard that makes
the persisting config surface unreachable from this driver.

**Nothing in this plan runs against develop.** All of it is verified offline with the gate
closed; the armed run is plan 27-06.
</objective>

|----------|-------------|
| driver → develop shared calendar configuration | A persisting config write would clobber a value shared by every consumer of develop, with no restore path |
| driver → develop calendar rows | Holiday rows are created and must be provably removed |
| probe-created symbols → develop ingestor | A symbol we create can change the observable state of an endpoint we also verify, creating self-inflicted false drift |
| mutation payloads → committed schema baselines | A drifted baseline turns every future run into a false-positive divergence |

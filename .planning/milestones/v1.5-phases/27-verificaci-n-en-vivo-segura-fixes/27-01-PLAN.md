Close the three harness blockers that RESEARCH reproduced **by execution**, so that the
later live destructive run can actually record its own deliverable.

Today: (a) a single `append_finding` with a new fid destroys the human-triage prose of all
36 existing market-data findings (`Classification:` 36→0, `Resolution:` 34→0, file
22,201→11,580 bytes); (b) `main_market_data.py` resets its fid counter to 0 every run, so
the first 36 Phase-27 findings would be swallowed by the non-OPEN short-circuit while the
SUMMARY still claims `FINDING=N`; (c) `verify_cycle_closure("market-data-client")` returns
`(False, 34)` **today** — F-03..F-36 are `FIXED` without a `Regression:` bullet.

Purpose: nothing destructive may run before this lands (D-16/D-21/D-23/D-24). A finding
written to a no-op is worse than a finding not emitted — the run reports success having
lost its deliverable.
Output: an additive `extra_bullets` preservation path in the shared findings serializer, a
`max_existing_fid(pkg)` allocator-seed helper, 34 backfilled `Regression:` bullets, and
three pieces of regression coverage.

This plan touches **only** `verification/` and the findings markdown. It deliberately does
**not** touch `main_market_data.py` so it can run in parallel with plan 27-02.
</objective>

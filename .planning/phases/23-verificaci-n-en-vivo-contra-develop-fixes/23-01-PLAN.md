## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driver → develop API (`https://market-data-develop.bbsa.com.ar/api`) | outbound network egress carrying the Auth0 Bearer; responses are untrusted payloads |
| driver → Auth0 token endpoint (`MARKET_DATA_AUTH0_TOKEN_URL`) | client_credentials grant; client_secret leaves the process |
| driver → stdout / findings file / schema snapshots (committed) | redaction boundary — no credential or PII may cross into committed artifacts |

## STRIDE Threat Register (ASVS L1, block-on: high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Information Disclosure | driver stdout / summary lines | mitigate | Every print routes through `safe_print(..., secrets=[])`; the Bearer regex (`redaction.py:31`) masks any `Bearer <token>` reflection structurally. Never print a raw response dict or token. |
| T-23-02 | Information Disclosure | committed schema snapshots under `.planning/verification/schemas/market-data-client/` | mitigate | `schema_of` reduces payloads to keys+type-names only (no values) — PII-free by construction; raw payloads only ever land in gitignored `.planning/verification/captures/`. |
| T-23-03 | Denial of Service (self-inflicted false FAILED) | per-probe exception handling | mitigate | D-09: every probe catches package exceptions, `httpx.ConnectError`/`ConnectTimeout` (→ NO-DATA), and broad `Exception` (→ ERROR-MAP); an unreachable develop or closed market never propagates an uncaught exception that flips `main_verify.py` to FAILED. |
| T-23-SC | Tampering | package-manager installs | accept | No new npm/pip/cargo installs in this phase — all dependencies (`httpx`, `verification/`, `market_data_client`) already vendored/locked; no supply-chain surface introduced. |
</threat_model>

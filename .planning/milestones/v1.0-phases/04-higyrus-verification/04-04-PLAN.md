<objective>
Aplicar el fix oportunista descubierto en el live run de Plan 04-02 (Task 2.3): los 6 endpoints cuenta-dependientes de higyrus-client (get_movimientos/get_posicion_valuada/get_posiciones en sync+async) fallan en vivo con HTTP 400 `"Error en formato de fechas. Ingrese las fechas con formato dd/mm/yyyy"` porque httpx por defecto percent-encodea `/` como `%2F` en el query string, y el backend de Higyrus (IIS/ASP.NET en `https://becerra.aunesa.com/Irmo`) NO decoda `%2F` antes de validar el formato — entonces ve literal `"08%2F05%2F2026"` y lo rechaza. Este plan reemplaza el uso de `params={...}` en `_request` (sync y async) por pre-atachar el query string a la URL con `urllib.parse.urlencode(clean_params, quote_via=quote, safe='/')`, lo que preserva el `/` literal en el wire end-to-end (verificado: `httpx.URL('https://x/?fechaDesde=08/05/2026').query == b'fechaDesde=08/05/2026'`). Agrega 2 regression tests (1 sync + 1 async) en sección `# ------ Wire encoding ------` que assertean el wire-level shape vía `httpx_mock.get_requests()[0].url.query`. Plan es **opportunistic** (insertado entre Wave 2 y Wave 3) por la convención `feedback-fix-blockers-in-cycle`: el bug se fija dentro del ciclo de verificación, no se difiere.

Purpose: Sin el fix, Phase 4 no puede emitir `Verified-live: PASS` para HIGY-02 (3 de 5 endpoints fallan en vivo), HIGY-03 (no se pueden capturar payloads reales para diff bidireccional), HIGY-06 (parity probe pasa pero los probes downstream no), ni HIGY-07 (no se puede observar respuesta 204/empty en endpoints cuenta-dependientes porque nunca pasan del 400 de fecha). F-07 (`get_listado_cuentas` returns 0 vs smoke test 8771) queda OPEN — causa raíz distinta (probable session/server-side state), investigación deferida fuera de Phase 4.

Output: `_request` sync+async refactoreado para preservar `/` literal en query; 2 regression tests con wire-level assertions; suite mockeada completa sigue verde; mypy + ruff verdes; re-run del driver demuestra PASS=15 SKIPPED=1 (vs PASS=11 FAIL=0 FINDING=6 pre-fix); findings.md actualizado con F-01..F-06 RESOLVED + F-07 OPEN nuevo.

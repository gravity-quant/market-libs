<objective>
Build the driver-side mutation gate and wire the harness fixes from plan 27-01 into
`main_market_data.py`, so that the destructive probes added in plan 27-04 land on a driver
that is already safe, already records findings for real, and already validates cycle closure.

The existing `verification/mutation_gate.py::mutating_allowed()` cannot be reused: it
hard-imports `matriz_client` and validates **matriz's** base URL against a remarkets sandbox
host. Called from the market-data driver its second leg is vacuous — the env flag alone would
unlock writes against any base URL. That is precisely the false sense of security the gate
exists to prevent (D-01).

Purpose: this is ROADMAP criterion 1 — mutations run only behind an explicit env gate plus an
exact develop host. It is also the phase's central security control: this is the repo's
**first** destructive live verification, and RESEARCH confirmed there is no prior cleanup or
gating precedent to copy (D-25) — `main_matriz.py` has no mutation probes and its only guard
is a substring check, the documented anti-pattern.
Output: a package-agnostic parametrized gate with adversarial tests, a driver that seeds its
fid allocator and validates cycle closure, gate-refusal probes, and a source-level guard on the
skip-line shape.

Depends on 27-01 (the cycle-closure probe would report FAIL without the backfill; the seeded
allocator needs `max_existing_fid`) and on 27-02 (the calendar SHAPE-diff unwrap here assumes
the reconciled `CalendarDay`).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator environment → driver gate | An env variable is the sole human opt-in to destructive behaviour; anything looser than an exact-value check makes it accidentally satisfiable |
| resolved `base_url` → mutation authorization | An attacker-controlled or misconfigured base URL is the path by which a mutation reaches the wrong environment |
| driver instance → client instance | The gate boolean must reach the client through a route that cannot be bypassed by constructing a second, ungated client |
| driver stdout → `main_verify.py` classifier | Output shape decides whether a package is reported verified or skipped |

<objective>
Make the crash path fail **closed**.

30-10 built `_redacted_excepthook` to stop CPython's default excepthook from printing
`[<status>] <resp.text>` — the full upstream error body of an authenticated brokerage session — to
stderr when a probe lets an exception escape its narrow `except`. That fix genuinely works for every
exception the hook renders without incident, and the marker-planted subprocess test proving it is
real. But the hook has no error handling of its own, and CPython's contract for a failing excepthook
is to fall back to the **default** renderer. So the one function built to suppress the raw body
emits it verbatim the moment anything inside it goes wrong.

Purpose: this is the fifth consecutive cycle on the same vulnerability class — an upstream wire value
reaching an observable sink outside the single sanctioned renderer — and it is now open at the exact
site built to close it. A security boundary whose failure mode is "emit the thing you were built to
suppress" must fail closed.

Output: `main_iol.py` gains a static placeholder constant and a guarded emitter; `_redacted_excepthook`
calls the renderer inside a guard. `verification/test_main_iol_exception_redaction.py` gains a new
section 5 with the verifier's own reproduction as a regression test, a monkeypatch-free trigger, the
sink-failure cases, and a structural AST lock so the guards cannot be removed silently.
</objective>

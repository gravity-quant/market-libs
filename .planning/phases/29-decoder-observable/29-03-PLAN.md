<objective>
TRACER SLICE, part 2. Complete the higyrus end-to-end path: make strict mode
reachable from public API, carry it to the decoder through a ContextVar bound at
the top of both `_request` implementations, and ship the two-part
`RedactingFilter` fix with a caplog sentinel proving the new emission path leaks
nothing.

After this plan, one package demonstrates the whole DEC-01 behaviour: a driver
can ask for strict mode, a divergence raises with its field path, and the same
divergence in observable mode is a structured record that a credential literal
provably never reaches.

Purpose: the decoder is called from parsers that hold no reference to the
`Client`. A ContextVar is the only carrier that survives interleaved async tasks
and does not force a `strict` parameter through roughly thirty pure parser
signatures — which would break the preserved `from_api(payload)` contract.
Output: `strict_decode` on `_ClientState` and on four public entry points, two
bind sites, the filter fix, and the sentinel.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer → `Client` / `configure` | The strict-decode flag is now settable from public API; it changes whether a data condition becomes an exception. |
| `_request` → decoder execution context | The mode crosses from per-instance state into a ContextVar read much later, by code that holds no client reference. |
| `extra=` payload → `RedactingFilter` → consumer handlers | Every log record any caller produces now traverses a recursive scan. |

<objective>
Build the sync/async parity apparatus — the affirmative substitute for the twice-abandoned
codegen requirement (DT-04, REFAC-06 shelved after two signed NO-GOs) — and use it to close the
one real drift it finds.

The design constraint that shapes everything here: a naive `get_type_hints(sync) ==
get_type_hints(async)` comparison is red in **all six** packages on day one, because the async
surface correctly takes an `httpx.AsyncClient` where the sync surface takes an `httpx.Client`.
Five of those six divergences are required correctness. Without a sanctioned normalization rule
the suite is red across the board and market-data's genuine defect is buried in the noise.

So this plan lands the helper with its rule table first, uses market-data as the pilot that
demonstrates the drift as a **failing test**, and then closes it. Plan 32-06 fans the frozen
helper out to the remaining five packages.

Purpose: make an undeclared sync/async divergence impossible to keep.
Output: `tools/surface_parity.py`, the market-data pilot test, and the D-09 fix.
</objective>

## Assumptions (flagged — unverified)

- **Interruption / parallelism safety of the phase's new gates is asserted by construction, not
  verified.** The parity helper is read-only: it imports modules and introspects them, writing
  nothing. Package imports do execute `load_dotenv()`, which is process-local and idempotent, and
  CI runs one package per matrix leg with no shared mutable state. Two concurrent runs would
  therefore be independent and an interrupted run leaves no partial state — but nobody has
  exercised either case. Recorded as an open assumption, not a verified property.
- **A3 (RESEARCH.md):** the new `http_client` parameter is purely additive and not
  source-breaking. Near-zero risk because it is keyword-only, but a consumer wrapping `configure`
  positionally was not surveyed.
- **Rule 3's module-level asymmetry** rests on the measurement that no sync surface exposes a
  module-level `close` shim. If one is ever added, rule 3 must change from a drop to a rename at
  the module axis too.
- **`get_type_hints` resolves for every public callable** (measured 347/347 today). The helper
  lets failures propagate rather than skipping, so a future `TYPE_CHECKING`-only import will
  surface as a loud failure rather than a quietly shrunken comparison — which is the intended
  behaviour, but means such a change reddens the suite before anyone has read this note.

`schema_of` (D-12), the two-stage capture→anonymize→fixture pipeline (`capture` to a gitignored
staging dir per D-11, `anonymize` with a per-package `Denylist` per D-10), the findings-file

pipeline, and a keys+types schema-snapshot tool. This plan builds all of that generic infra
(NOT a real snapshot — the first snapshot is committed in Phase 2, DRIFT-01) and proves the
PII-safety property structurally: raw payloads land only in the gitignored `captures/` dir,
anonymize strips PII while preserving bug-reproducing format, and schema_of emits no values.

`verification/findings.py`, the `.planning/verification/FINDINGS-TEMPLATE.md` template, a

| anonymized fixture → committed test | A fixture committed under packages/<pkg>/tests/ must contain no real PII yet still reproduce the bug (HARN-06/D-10) |
| schema snapshot → committed file | A snapshot file (built here, committed Phase 2) must be PII-free by construction |

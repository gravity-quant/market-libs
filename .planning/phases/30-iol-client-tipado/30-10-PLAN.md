approach_decision:
  id: "AD-30-10-01"
  question: >
    Close the crash-path leak with a `sys.excepthook` override installed at the `__main__` guard, or
    by wrapping the body of `main()` in a top-level try/except that re-raises?
  chosen: "a named `sys.excepthook` override, installed by a named installer function from the `__main__` guard"
  reversibility: "two-way"
  rationale: >
    A try/except inside `main()` would bind the escaping exception to a name inside an
    `ast.ExceptHandler`, which is exactly the node shape `_raw_exception_renders` walks — the fix
    would then have to survive its own regression lock, and any future author touching it would be
    editing code the lock inspects. Worse, a wrapper in `main()` covers only exceptions raised
    under `main()`; it misses anything raised at import time or after `main()` returns, and the
    driver's module body runs `load_dotenv()` through the `iol_client` import chain. An excepthook
    is process-wide, is installed in exactly one statement, and delegates rendering to the single
    sanctioned renderer rather than reimplementing redaction — which is the property AD-30-09-01
    exists to protect. Reversible: two private functions plus one statement in a non-published
    driver script; no package source, no committed baseline, no public API, no dependency.

<objective>
Close the two BLOCKERs that 30-VERIFICATION.md's fourth cycle left open, both in `main_iol.py`,
the phase's live-verification driver.

**Gap 1 (truth 7).** The driver's finding-ID allocator starts at zero on every process start, so the
next live run collides with the two already-triaged findings committed in
`.planning/verification/iol-client-findings.md`: it rewrites `F-01` (OPEN) in place with unrelated
content and silently discards the finding it tries to file as `F-02` (FIXED), while the printed
`SUMMARY` still reports success. Seed the allocator from `max_existing_fid(_PKG)` the way the
sibling driver `main_market_data.py` already does.

**Gap 2 (truth 8).** The 32-site sweep delivered by 30-09 closed every *caught*-and-reported path.
The *uncaught* path is untouched: an exception escaping a probe's deliberately-narrow `except`
clause reaches Python's default `sys.excepthook`, which renders the exception's message — and for
`IOLAPIError`/`IOLAuthError`/`IOLRateLimitError` that message is `f"[{status}] {resp.text}"`, the
full upstream response body from an authenticated brokerage API — to stderr, which CI captures.
Install a redacted excepthook that renders only the sanctioned `_redacted_exc(exc)` plus a
frame-only traceback, and still lets the process die.

Purpose: the phase's roadmap goal (SC1-SC5, the typed public surface of `iol-client`) has been
fully met and regression-confirmed in four consecutive verification cycles. What remains open is
the phase's own additionally-declared harness guarantee — that `main_iol.py` never leaks an
upstream wire value to an observable sink, and that its own reporting can be trusted. These two
defects are the last two open items on that guarantee.

Output: three new symbols in `main_iol.py`, one new offline test file, one new section in the
existing redaction contract file. Zero changes under `packages/`.
</objective>

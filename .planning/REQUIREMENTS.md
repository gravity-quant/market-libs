# Requirements: market-libs — v1.3 Codegen Single-Source (libcst)

**Defined:** 2026-07-02
**Core Value:** Cada divergencia entre un cliente y su API en vivo debe ser detectada, documentada y corregida. (v1.3 layer: cerrar el único unknown arquitectónico residual — eliminar la duplicación estructural sync/async de los transport shells `client.py`/`aio.py` × 4 paquetes vía codegen single-source, sin degradar la fidelidad ni la verificabilidad de ningún cliente.)

**Milestone goal:** Resolver — o descartar definitivamente — REFAC-06 (codegen single-source sync/async) mediante una spike AST-level con `libcst >=1.8.0,<2` que cierre los 3 items FAIL del gate anterior (unasync NO-GO en v1.2 Phase 12 por *source-shape asymmetry*). REFAC-06 está **spike-gated** por la decisión locked D-NOGO-01: SPIKE-006 corre primero; el codegen × 4 se implementa **solo si** el spike retorna GO.

**Scope packages:** `iol-client`, `higyrus-client`, `ambito-financiero-client`, `matriz-client`. Excluido: `wallets-client` (stub).

**Non-breaking:** v1.3 es un bump minor y un refactor 100% interno — la API pública top-level (`pkg.get_X(...)`, `pkg.configure(...)`, `Client`/`AsyncClient`) se mantiene 100% backwards-compatible. El codegen solo reescribe la *forma fuente* de los transport shells, no su comportamiento observable.

## v1.3 Requirements

### Codegen tool-choice spike (CODEGEN)

- [x] **CODEGEN-01**: Evaluar `libcst >=1.8.0,<2` como herramienta de codegen AST-level para
  single-source sync/async, contra un gate **`D-RIGOR-02` de 10 items**, y firmar una decisión
  binaria **GO / NO-GO**. Vehículo: SPIKE-006 (spike-before-plan, mismo patrón que v1.2 Phase 12).

  - **Canary:** `packages/ambito-financiero-client/.../aio.py` en su **forma v1.2-head** (NO migrada) —
    el spike debe producir un `client.py` byte-idéntico al hand-written **sin** requerir los ~30 LOC
    de migración de source que unasync necesitaba.

  - **Los 3 items que unasync no pudo cerrar** (todos trazados a un único root cause, source-shape
    asymmetry) y que libcst DEBE cerrar para GO:

    - *Item 1/6 — import-direction asymmetry*: `aio.py` importa `_validate_max_retries` DESDE `client.py`;
      un `ImportDirectionNormalizer` (CSTTransformer) mueve la definición y reescribe el import (evita
      el self-import circular de unasync).

    - *Item 4 — single-line import-order asymmetry*: `from <pkg> import _transport, _core` (no
      alfabético); un `ImportNormalizer` reordena los `cst.ImportAlias`.

    - *Item 1 (H1/H8/H9) — docstring localization*: `sincrónico`↔`asincrónico`, `Client`↔`AsyncClient`;
      un `DocstringLocalizer` reescribe el valor del `cst.SimpleString`.

  - **8 items heredados de SPIKE-005** (PASS esperado, no re-derivar el diseño): B8 identity invariant,
    `@generated` marker (PEP 263/236), `ruff format --check`, `ruff check` (incl. ASYNC1xx),
    `mypy --strict`, `lint-imports` (4 contracts), `@generated` × `from __future__ import annotations`.

  - **2 items nuevos libcst-específicos:** (9) los CSTTransformer subclasses son funciones puras
    `CSTNode → CSTNode` sin estado global ni side-effects; (10) matriz construct audit (109 rows, 0
    unresolved) + deny-list intactness (`_token_store.py`/`_refresh_policy.py`/`_refresh.py`/`ws_client.py`
    sha256-byte-idénticos) re-verificados bajo `libcst.MetadataWrapper` per-file scope.

  - **Salida:** GO/NO-GO firmado + per-package CSTTransformer drafts. **Si items 1/4/6 FAIL de nuevo →
    REFAC-06 se archiva permanentemente** (los shells duplicados quedan como feature estructural aceptado).

### Codegen single-source sync/async (REFAC)

- [ ] **REFAC-06** *(CONDITIONAL on CODEGEN-01 GO — DROPPED si SPIKE-006 retorna NO-GO)*: los transport
  shells `client.py`/`aio.py` de los 4 paquetes verificables (ámbito → iol → higyrus → matriz) se
  single-sourcean vía libcst codegen. Deliverables:

  - Script de codegen (`scripts/codegen.py` o equivalente) invocable vía `make codegen` / `uv run --with libcst`.
  - `@generated by libcst` marker (PEP 263/236) al tope de cada archivo generado.
  - **CI `lint-codegen` verify-clean job**: `make codegen-check` → `git diff --exit-code` (anti-Pitfall 5:
    hand-edit sobre archivo generado falla CI).

  - **B8 identity preservada** (anti-Pitfall 4): `client._raise_for_response is aio._raise_for_response is
    _core.raise_for_response` — test corre PRIMERO en CI.

  - `ruff format`/`ruff check`/`mypy --strict`/`import-linter` (4 contracts) clean sobre los 8 archivos generados.
  - Suites mockeadas (pytest-httpx, sync+async) verdes vs código generado × 4 paquetes.
  - `libcst >=1.8.0,<2` agregado a root `[dependency-groups] dev` (dev-only; no toca runtime deps de los paquetes).
  - **Deny-list respetada:** matriz `_token_store.py`, `_refresh_policy.py`, `_refresh.py`, `ws_client.py`
    NO se tocan (sync/async paths no-isomorphic). Codegen aplica SOLO a los transport shells `client.py`/`aio.py`.

## In-cycle verification convention

REFAC-06 es un refactor estructural: el gate `D-RIGOR-02` item 1 (byte-identical round-trip) + item 6
(mocked suite green vs generated) son la verificación primaria — si el output generado es byte-idéntico al
hand-written, el wire behavior no cambia por construcción. No se planifica un re-run live × 4 completo salvo
que el output generado diverja del hand-written (en cuyo caso se aplica la taxonomía operator-driven
CONFIRMED/FIXED/EXPECTED/NO-FIX en el mismo phase, patrón v1.0/v1.1/v1.2). Tracking vía `verification/findings.py`
append-only si aplica.

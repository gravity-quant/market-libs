<objective>
Close CR-01: restore real schema-drift detection to the `iol-client` verification harness.

`_as_wire()` projects a model back to a dict via `dataclasses.asdict`. By the time a model
exists, the Phase 29 walker has already coerced every non-optional field to its declared
type and discarded every undeclared wire key — so `schema_of(_as_wire(model))` is a constant
function of the model *declaration*, not of the wire. Verified empirically twice (code review
and verification) against the real committed `get-quote.json` baseline: a `ultimoPrecio`
float→str change, an added `simbolo` key, and a removed `montoOperado` key are each detected
on the raw wire and each invisible through the projection.

This defeats `probe_schema_snapshot` on 3 of 4 endpoints and both `probe_field_type_map`
loops, and it contradicts CLAUDE.md's Core Value directly — "cada divergencia entre el
cliente y el servicio en vivo debe ser detectada". Phase 33 (live strict verification)
depends on this signal.

Purpose: the drift probes must again be a function of what the API actually returned. The
typed models remain exactly as delivered and keep serving the typed-access probes; what
changes is which payload the drift probes read.

Output: a raw-wire capture helper, two rewired probes, an offline regression test that
locks the fix against reversion, and two folded false-positive fixes in the same file.
</objective>

<approach>
## The fix, stated once

Capture the raw body **once per endpoint** and thread it to the two drift probes, exactly
the way the by_type envelope is already threaded from probe 12 to probe 13 today. Models
continue to flow to the typed-access probes (3-10) and to the parity probe (11) unchanged.

This is not a new pattern. `probe_field_type_map` already performs one raw `client._request`
for the by_type envelope, documented as "la ÚNICA HTTP call duplicada permitida (Pitfall 2)"
precisely because the wrapper silences the drift the probe exists to catch. CR-01 is that
same argument, discovered to apply to three more endpoints. The change generalizes an
existing, already-reasoned exception rather than inventing a mechanism.

Cost: three additional authenticated GETs per live run, on a token already cached by the
auth-once discipline. The run already issues roughly fifteen, six of them in the by-type
sanity loop.

## Why capture is separated from checking

`_capture_raw_wire` does the I/O and nothing else. `probe_field_type_map` and
`probe_schema_snapshot` become pure functions of a supplied `raw_wire` dict. That seam is
what makes Task 1's regression test possible offline, with no credentials, no network and
no HTTP mocking — the same property that let this phase's earlier plans verify a round-trip
against the committed baseline without a live run.

## What must NOT change

- The four committed baselines under `.planning/verification/schemas/iol-client/` stay
  byte-identical. They are `schema_of(raw)` documents; feeding raw wire is what makes the
  comparison valid again, so a correct fix produces no diff there.
- D-25 no-overwrite-on-drift stays intact: drift produces a finding, never a write.
- `probe_parity_sync_async` (probe 11) keeps `_as_wire`. WR-07 is out of scope; only its
  docstring is corrected to stop overstating what a PASS there proves.
- The typed models, `models.py`, `_core.py`, `client.py`, `aio.py`, the RED fixture, the
  README changelog and the surface snapshot are all out of scope. This plan touches one
  driver file and adds one test file.
</approach>

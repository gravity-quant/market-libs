    Extender `verification/findings.py` con `append_finding(...)` siguiendo el bosquejo de 02-PATTERNS.md sección 1 y 02-RESEARCH.md Pattern 1.

    Firma exacta (mypy strict, `from __future__ import annotations` ya está en línea 19 — mantener):

    ```
    def append_finding(
        pkg: str,
        *,
        fid: str,
        class_: str,
        surface: str,
        status: str,
        title: str,
        expected: str,
        actual: str,
        diff: str,
        regression: str | None = None,
        base_url: str | None = None,
        market_hours: str | None = None,
    ) -> Path: ...
    ```

    Estructura interna recomendada (Discretion: detalle interno del parser):
    - Helper privado `_Finding` como `@dataclass(frozen=True, slots=True)` con campos `fid, class_, surface, status, title, expected, actual, diff, regression: str | None`
    - Helper privado `_parse_findings(text: str) -> tuple[list[_Finding], dict[str, str]]` lee el archivo línea por línea: captura `## Run Context (ART)` block en `dict` con keys `"Timestamp"`, `"Resolved base URL / env"`, `"Market hours note"`; detecta tabla `## Index` y `### F-NN -- ...` headers para reconstruir la lista de findings
    - Helper privado `_serialize_findings(pkg: str, findings: list[_Finding], art: dict[str, str]) -> str` re-renderiza el archivo entero (header + ART + comentarios `<!-- Clases -->` + `<!-- Estados -->` + tabla `## Index` + sección `## Detalle por hallazgo` + un `### F-NN` block por finding usando el formato verbatim de `FINDINGS-TEMPLATE.md` líneas 67-85)
    - El cuerpo de `append_finding`:
      1. Validación: `if class_ not in FINDING_CLASSES: raise ValueError(...)`; mismo para `status not in STATUS_LIFECYCLE`
      2. `path = findings_path(pkg)`; `if not path.exists(): write_findings(pkg)` (reusa idempotencia existente)
      3. `text = path.read_text(encoding="utf-8")`
      4. `findings_list, art = _parse_findings(text)`
      5. Refrescar ART: `art["Timestamp"] = dt.datetime.now(dt.UTC).isoformat()`; if `base_url is not None`: `art["Resolved base URL / env"] = base_url`; if `market_hours is not None`: `art["Market hours note"] = market_hours`
      6. Idempotencia por fid: construir `existing = {f.fid: f for f in findings_list}`; si `fid in existing and existing[fid].status != "OPEN"`: re-serializar tal cual (solo ART cambia), return path
      7. Construir `new = _Finding(fid, class_, surface, status, title, expected, actual, diff, regression)`
      8. Si `fid in existing`: reemplazar in-place (`findings_list = [new if f.fid == fid else f for f in findings_list]`); else: append
      9. `path.write_text(_serialize_findings(pkg, findings_list, art), encoding="utf-8")`; return path

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driver/test → findings file (markdown) | Mutaciones idempotentes a archivo committeable; preservación de status promovido por humano |
| driver → ART block | Refresco automático del Timestamp + base_url en cada call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | append_finding sobreescribiendo status humano CONFIRMED/FIXED/EXPECTED/NO-FIX en re-runs | mitigate | Por diseño: si `fid` existe con status != "OPEN", el helper NO toca el finding (Pitfall 1 de 02-RESEARCH.md). Test 3 (D-10 invariante) verifica el comportamiento explícitamente. |
| T-2-02 | Tampering | Parsing frágil de markdown con regex que pierde campos multilínea | mitigate | Patrón 1 de 02-RESEARCH.md: modelo interno (`_Finding` dataclass) + re-serializar archivo completo desde modelo, no regex spot-edits. |
| T-2-03 | Repudiation | ART block no actualizado deja runs sin trazabilidad | mitigate | append_finding refresca Timestamp + base_url + market_hours en cada call (Test 4 verifica). Open Question 1 de 02-RESEARCH.md resuelta: el ART se refresca dentro de append_finding mismo. |
| T-2-04 | Information Disclosure | Findings file accidentalmente committee credenciales si un payload con secrets es pasado en `expected`/`actual`/`diff` | accept | Phase 2 driver no tiene credenciales (Ámbito sin auth). En Phases 3-5 el llamador debe pasar payloads previamente redactados via `safe_print` o anonymize. No hay capa de redacción dentro de append_finding por diseño (separación de responsabilidades). |
| T-2-05 | Tampering | class_/status inválido produce findings rotos | mitigate | Validación temprana: `ValueError` si `class_ not in FINDING_CLASSES` o `status not in STATUS_LIFECYCLE` (Tests 5 y 6). |
| T-2-SC | Tampering | npm/pip/cargo installs | accept | No se instalan paquetes externos en este plan; sólo stdlib + dataclass + datetime ya en uv.lock. Audit table en 02-RESEARCH.md sección "Package Legitimacy Audit" — vacía intencional. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test suite → committed snapshot files | Snapshot files are committed to git; CI compares against them. A malicious or accidental snapshot edit could mask a public-surface regression. |
| Operator → regen script | Operator runs `python verification/regen_snapshots.py` manually; the diff lands in a commit. Human review at PR time is the trust anchor. |
| Phase 6 → future phases (baseline file) | The committed baseline file is the authoritative pre-refactor test count + coverage. Future phases diff against it; if it is mutated retroactively, regression detection is masked. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `verification/regen_snapshots.py` | mitigate | The snapshot file header is a comment block that warns "DO NOT EDIT BY HAND" and names the regen command. Final defense is human review of the snapshot diff at PR time (Pitfall #8 in RESEARCH.md). Test in Task 2 strips header lines from expected before compare, so editing the header does not mask body drift. The 8-line header invariant pinning (W3) means structural drift is detected too. |
| T-06-08 | Information Disclosure | snapshot file contents | accept | Snapshot lines contain only public symbol names + signatures from `__all__`. Credentials and tokens are never in `__all__` (`_state` is private). RESEARCH.md Security Domain (V8) confirms this is verified by enumeration of public surface only. |
| T-06-12 | Tampering | `verification/baselines/phase-06-baseline.txt` retroactive edit | mitigate | File embeds a `git_sha:` field at capture time so a retroactive edit is detectable by comparing against `git log -p` history. PR review is the final gate. |
| T-06-SC | Tampering | npm/pip/cargo installs | N/A | No packages installed by this plan. |
</threat_model>
